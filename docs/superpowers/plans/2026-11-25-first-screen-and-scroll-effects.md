### Task 2: The words move into `site-text.txt`

**Files:**

- Test: `tests/test_sitetext.py`, `tests/test_build.py` (create)

**Interfaces:**
- Produces, in `sitetext.py`:
  - `class SiteTextError(Exception)`: `str()` is one plain sentence starting `site-text.txt line N:` (or `site-text.txt:` when no line applies).
  - `parse(text: str) -> dict[str, list[str]]`: keys are section names lower-cased with runs of spaces collapsed; values are paragraphs. Lines starting with `#` are ignored. A blank line ends a paragraph; consecutive non-blank lines join with one space; a line starting with `- ` starts a new paragraph (a list item) without the `- `. Trailing spaces are stripped.
  - `load(path: pathlib.Path, sections: Sequence[str]) -> dict[str, list[str]]`: reads bytes, decodes `utf-8-sig`, normalises `\r\n` and `\r` to `\n`, parses, then raises `SiteTextError` for: an unknown section (names the line and lists known sections), a missing section, an empty section (names the header line), an em dash U+2014 or en dash U+2013 (names the line and the section and says to use a comma, colon or parentheses).
  - `inline(text: str, root: str = "") -> str`: escapes `&`, `<`, `>` (quote=False); turns `[words](address)` into `<a href="address">words</a>`, prefixing `root` when the address is relative (not starting with `http:`, `https:`, `mailto:`, `#` or `/`); escapes `"` inside the address; leaves anything that is not a complete `[...](...)` as escaped text.
  - `split_item(paragraph: str) -> tuple[str, str]`: splits on the first ` | `; raises `SiteTextError` naming the paragraph's first 40 characters when there is none.
- Produces, in `build.py`: constant `SECTIONS` (the list below, in file order); `TEXT = sitetext.load(...)` before anything is written; an optional third argument, the path of the text file (default `site-text.txt` beside `build.py`); on `SiteTextError` print the message to stderr and exit with status 2.
- Sections (exact names; Task 4 and Task 6 add three more): `name`, `page description`, `tagline`, `bio`, `scroll cue`, `writing intro`, `writing note`, one `room note: <room title>` per entry of `SUBJECTS` (e.g. `room note: Philosophy and religion`), `atoms heading`, `atoms plate note`, `atoms lede`, `atoms text`, `atoms links`, `other software heading`, `other software text`, `other software link`, `areas`, `contact text`, `contact line`, `footer`.
- Rooms: today each room shows only its title (from `SUBJECTS`, which stays in `build.py` because it carries the anchors) and the note "First essay from 15 December"; that note is the room's `room note` section. The unused `ROOM_TEXT` dictionary in `build.py` stays unused; the redesign adds no room descriptions (spec: no new content).
- `atoms links` and `areas` are list sections; each item is `title | description`, where the title may be a `[words](address)` link. In `atoms links` a linked title gets the description in `<span class="d">`, an unlinked one in `<span class="soon">` (today's markup). `atoms plate note` holds the sentence without its plate number; the build prefixes `Plate {NO["alchemist-phosphorus.jpg"]}: `. `footer`'s relative link gets the page's `root`.
